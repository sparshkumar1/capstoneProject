## 2. Table pagination. **Done; the "still doesn't fit" fallback is implemented but not exercised.**
Every table built by `add_table()` (the 12 numbered content tables, 4.1–10.4) now: (a) chains every row to the next via `keep_with_next`, so Word keeps the whole table together whenever it fits on one page rather than breaking between arbitrary rows; (b) marks every row `cantSplit`, so a tall row's own content can't be divided mid-row; (c) marks the header row `tblHeader` to repeat if a table ever does span pages; (d) keeps each "**Table N.M.**" caption glued to its table via the same `keep_with_next` mechanism. All 12 tables in this report are small enough (max 7 rows, Table 6.1) that every one now renders whole on a single page with its caption — verified directly on Table 10.1 and Table 6.1's rendered pages. No table in this report is actually large enough to need the repeated-header fallback, so that specific path is implemented correctly but untested in practice.

## 3. Double-asterisk markers. **Done — found a real bug beyond the obvious case.**
Plain-paragraph `**bold**` markdown was already being converted to real bold formatting correctly before this pass. The genuine defect was in table cells: `add_table()` inserted raw cell text verbatim without running the markdown parser, so any cell written as `**bold**` rendered as literal asterisks in the PDF (confirmed on Table 10.1: `**Final result (post-fix)**`, `**93.3%**`, `**28/28 passed (100%)**`, `**Zero**`, 24 affected lines across the report). Fixed by extracting the existing inline-markdown parser into a shared `add_inline_runs()` helper used by both paragraphs and table cells. Verified: zero `**` remain anywhere in the rebuilt document, checked across every paragraph **and every table cell** (the first check only covered body paragraphs and would have missed this).
