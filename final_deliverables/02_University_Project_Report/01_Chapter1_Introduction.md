# Chapter 1: Introduction

Technical interviews constitute one of the most consequential gatekeeping mechanisms in the software-engineering hiring pipeline. Candidates are evaluated not merely on their knowledge of algorithms, data structures, and system design, but on their ability to reason coherently under time pressure, communicate their thought process clearly, and adapt to examiner prompts in real time. Despite these high stakes, the tools available for preparation have remained largely static. Platforms such as LeetCode, HackerRank, and InterviewBit present every candidate with the same pool of questions at fixed difficulty levels, with no mechanism for adapting to individual performance, no structured per-answer explanatory feedback, and no capacity to capture multimodal signals such as vocal confidence or hesitation.

PrepAIred is designed to narrow this gap. It is an agentic technical-interview preparation platform integrating reinforcement-learning-based difficulty adaptation, rubric-anchored semantic evaluation, prosodic audio analysis, and large-language-model-driven hint and feedback generation within a multi-agent architecture coordinated by a central orchestrator. A Proximal Policy Optimisation (PPO) agent selects a discrete action — **Easier, Same, or Harder** — from a six-dimensional state vector encoding answer quality, concept coverage, audio confidence, hesitation, session progress, and current difficulty. A post-inference guardrail layer of six deterministic rules overrides the policy where its raw recommendation would be pedagogically unsound. Semantic evaluation combines Sentence-BERT similarity, FAISS-based concept-coverage scoring, and CrossEncoder reasoning-quality assessment into a rubric-anchored composite score, with a locally hosted Qwen2.5 model invoked selectively for partial-credit adjustment and contextual hint generation. After every answer, a FeedbackAgent produces a structured fifteen-field report covering misconception detection, concept-gap identification, and audio-derived communication analysis.

## 1.1 This Phase's Contribution

Phase-2 of this capstone project (`revised_report_v5.pdf`, submitted Jan–May 2026) delivered the complete implementation described above. **This phase (Phase-3) does not change that implementation's core architecture.** Its contribution is a comprehensive, evidence-based testing and verification programme, executed in four stages:

1. **Inspection** — a line-by-line reconciliation of every architectural and numerical claim in the Phase-2 report, the project's internal reference documentation, and the actual source code, which surfaced **eight confirmed factual discrepancies** (detailed in Chapter 10) — including an inaccurate description of the evaluator's fallback mechanism, an incorrect claim that question selection uses FAISS semantic retrieval (it is rule-based), an incorrect RL action-space size, an incorrect PPO training step count, and an unsupported headline accuracy figure in the Phase-2 abstract that traces to no stored artifact.
2. **Comprehensive testing** — a project-specific test strategy covering 22 testing categories plus dedicated ML and RL evaluation, classified by actual relevance to this codebase rather than applied generically; execution of the existing 25-file, 28-file (frontend) automated suite; and 11 newly authored, independently executed test scripts covering RL-policy inference sanity, guardrail-boundary verification, evaluator API contracts, adversarial/edge-case input handling, database relational integrity, security-configuration review, compatibility notes, and structured UI inspection.
3. **Diagnosis and justified improvement** — testing surfaced two genuine defects, not previously known: a guardrail-coverage gap that could allow difficulty to be escalated for a below-average-scoring candidate with no safety check intervening, and a platform-specific crash in the application launcher on Windows consoles. Both were diagnosed, fixed with minimal, scoped changes, and verified via full regression testing with zero new failures.
4. **Results consolidation** — a single master results table and a full reproducibility record (git commit, environment, exact rerun commands), so every number in this report traces to a stored log or script.

## 1.2 Scope and What Is Not Claimed

Consistent with the evidence discipline applied throughout this phase, this report does not claim results that were not measured. In particular: no new PPO training, retraining, or reward/state/action redefinition was performed (the deployed policy and the project's existing frozen research results are cited, not reproduced or altered); no formal human-subject usability or learning-outcome study was conducted (this remains explicitly identified as future work, both in the Phase-2 report and here); speech-transcription word-error-rate accuracy is not claimed, since no verified reference-transcript dataset exists in this project; and a proposed multi-agent "bounded-authority coordination layer" described in a separate research-paper draft supplied alongside this report was found, on inspection, not to exist in the codebase — it is explicitly excluded from this report's architecture description (see Chapter 10 and the accompanying research-paper scope decision).
