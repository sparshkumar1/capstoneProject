\section{Experimental Methodology}\label{sec:method}

\noindent\textbf{Evaluation Environment and Replay Dataset.}
To evaluate coordination and specialization without stochastic variance from live network calls, all experiments run via deterministic replay through the real orchestrator hub with \texttt{EVALUATOR\_MOCK\_MODE=1}. All experiments operate on a fixed set of 64 technical-interview replay instances across eight underlying replay clusters prepared for the proposed system, combining constructed (authored) answer payloads with team-generated/synthetic instances. Each replay cluster corresponds to the $k$-th recorded answer set across the eight interview questions ($k = 1, \dots, 8$). In replay mode, the hub consumes these fixed evaluator inputs directly, driving the full state machine and coordinator. Evidence classes are labeled by experiment: REPLAY (XA, XC, and the open-loop split versus unified comparison), FAULT-INJECTED (XB, faults injected into the real agents during replay), and SYNTHETIC (the authored feedback probes of XD and the guardrail state-grid analysis). For follow-up probes, the replay reuses the recorded evaluator payload associated with the root concept rather than generating a new candidate response. Replay sessions combine the 8 underlying replay clusters with 20 question orders (order seeds 0--19; seed 0 is the original order), yielding $N = 160$ sessions per experimental condition. These 160 sessions are \textbf{not independent}; they reuse the identical 8 replay clusters. We therefore explicitly model the 8 underlying replay clusters as the independent structural units in the cluster-aware analyses. No live generative LLM is invoked during replay; the LLM gateway is stubbed as down and deterministic template renderers handle text output, so trajectory differences are evaluated under fixed stimuli without live-model stochasticity. Per-turn latency was timed in-process with a monotonic wall-clock timer around each orchestrator call, with the order of conditions within each replay cell shuffled to control drift. Runs used Python 3.11 with dependency versions outside the repository's pins; CPU, hardware, and operating-system details were not recorded, so latency is reported as a paired overhead between conditions rather than as absolute performance.

\noindent\textbf{Baseline and Ablation Matrix.}
To address RQ1 (coordination dynamics), RQ3 (coordination mechanisms), and RQ4 (authority and safety boundaries), we evaluate the baseline platform alongside controlled ablation conditions (Experiment XA) across the identical 160 replay sessions:
\begin{itemize}\setlength{\itemsep}{0pt}\setlength{\parskip}{0pt}\setlength{\parsep}{0pt}
\item \textbf{Frozen Baseline ($B_0$):} Single-controller workflow without agents, with PPO active and deployed inline guardrails.
\item \textbf{PPO-Disabled Baseline ($B_7$):} Single-controller baseline with PPO unavailable, using deterministic rule fallback.
\item \textbf{Canonical-Guardrail Baseline ($B_{0c}$):} Baseline evaluated with canonical \texttt{rl/guardrails.py} instead of inline rules.
\item \textbf{Full Multi-Agent System ($M_1$):} Strategy and Coaching agents, peer messaging, and arbitration ($\tau = 0.6$).
\item \textbf{Strategy Agent Ablated ($M_2$):} Strategy disabled while Coaching and the coordination layer remain active.
\item \textbf{Coaching Agent Ablated ($M_3$):} Coaching disabled while Strategy remains active, testing trajectory independence.
\item \textbf{Arbitration Ablated ($M_4$):} Raw Strategy proposals admitted without confidence-threshold, evidence-grounding, or step-bound checks.
\item \textbf{Grounding Verification Ablated ($M_5$):} Coaching plans accepted without concept-evidence grounding checks.
\item \textbf{Peer Communication Ablated ($M_6$):} Strategy-to-Coaching peer messaging disabled, isolating message exchange.
\item \textbf{Authority Enforcement Ablated ($M_8$):} Score authority verification bypassed before proposal admission.
\item \textbf{PPO-Disabled Multi-Agent ($M_7$):} Full multi-agent system with PPO disabled, falling back to rule heuristic (paired with $B_7$).
\item \textbf{Canonical-Guardrail Multi-Agent ($M_{1c}$):} Full multi-agent system evaluated with canonical guardrails.
\end{itemize}

\noindent\textbf{Framework for Evaluating Agent Specialization (RQ2).}
To evaluate whether decomposing technical coaching into specialized agents produces measurable behavioral divergence or operational trade-offs compared to a unified controller (RQ2), we formulate a controlled comparative framework contrasting: (1)~\textbf{Specialized Architecture ($M_{\text{split}}$):} The two-agent baseline ($M_1$) partitioning responsibilities across Strategy and Coaching with separate state ledgers and explicit peer messaging; and (2)~\textbf{Unified Architecture ($M_{\text{unified}}$):} A monolithic agent (\texttt{UnifiedCoachAgent}) maintaining a joint session ledger and synthesizing difficulty actions, follow-up probes, and coaching plans in a single dispatch. To ensure an equivalent comparison, both configurations receive identical observation inputs, identical question sequences, identical heuristic decision thresholds, and identical arbitration rules. We evaluate four measured outcomes alongside one architectural property: (1)~decision agreement rate ($\mathbb{P}(\text{Decision}_{\text{unified}} = \text{Decision}_{\text{split}})$); (2)~difficulty-action agreement and (3)~follow-up probe agreement, both components of (1); (4)~per-turn dispatch and serialization latency; and (5)~architectural state encapsulation (schema separation and separate ledger boundaries).

\noindent\textbf{Threshold Decomposition (Experiment XC).}
Because the unarbitrated condition ($M_4$) simultaneously removes the confidence threshold, evidence verification, and one-step limits, it cannot isolate which mechanism prevents oscillation collapse. We therefore execute Experiment XC, sweeping the confidence threshold $\tau \in \{0.0, 0.5, 0.6, 0.7, 0.8, 0.9\}$ across the same 160 replay sessions while holding all other guardrail boundaries and evidence checks active. Five predictions were registered before any XC run, with $\tau = 0.6$ fixed in advance: (C1)~at $\tau = 0.0$, mean PPO agreement below 0.10, fewer than 5.0 mean level changes per session, and no session with guardrail bypass; (C2)~$\tau = 0.6$ reproduces the $M_1$ difficulty, score, and question paths in every session; (C3)~$\tau = 0.5$ equals $\tau = 0.6$ in every session; (C4)~the mean number of decisions taken from a Strategy proposal is non-increasing over $\tau = 0.6, 0.7, 0.8, 0.9$; and (C5)~at $\tau = 0.9$ that mean is below half its value at $\tau = 0.6$.

\noindent\textbf{Fault Injection and Circuit Breaker (Experiment XB).}
To test whether bounded authority contains component failures (RQ4), constructed faults were injected into the real agents during replay. One registered, explicitly exploratory prediction concerned the per-agent circuit breaker: in the crash, malformed, stale, and NaN-confidence cells with the full path, the breaker would open at least once in at least 80\% of sessions (expected from the 0.3 fault rate and a 60\,s cooldown). Strategy faults were crash, timeout, malformed output, forbidden state key, stale version, NaN confidence, and \emph{adversarial-valid} (a well-formed, authorized proposal opposing the evidence); Coaching faults were crash, malformed output, stale version, and \emph{ungrounded} (a valid plan emphasizing a concept absent from the evaluator evidence). The adversarial-valid and ungrounded faults fired on every call; all other faults fired with probability 0.3 per agent call (seeded), and the real agent ran on the remaining calls. Each fault was crossed with four variants (full path, authority check removed, arbitration removed, grounding check removed) over 40 sessions per cell (8 clusters $\times$ 5 order seeds), with a 150\,ms agent timeout. A fault counted as contained only if the session completed, committed scores equaled the evaluator output, and every difficulty transition was valid; guardrail bypass, ungrounded-concept leakage, and circuit-breaker opening (at least once per session) were counted per session. Because each variant removes a mechanism and then injects the fault it guards against, the results show the necessity of a mechanism for the tested property, not general fault tolerance.

\noindent\textbf{Grounding Probe (Experiment XD).}
Separately from the proposal-level concept-grounding check, the deployed lexical feedback validator was probed with authored (synthetic) feedback texts; no LLM was involved. For each of the 64 recorded evaluator payloads, seven constructed feedback categories were checked (for example faithful text, a score leak, and \emph{truncated paraphrase credit}, which credits a concept in paraphrase without supporting evidence). Placeholder concept texts in the stored payloads were relabeled uniquely to remove an evidence artifact, and a category was counted only for payloads where it could be constructed. We report how often unsupported paraphrased credit was accepted; acceptance shows that the validator enforces a lexical evidence contract rather than semantic correctness.

\noindent\textbf{Statistical Methodology.}
For session-level point estimates and paired differences, we compute standard non-parametric percentile bootstrap intervals with $B = 10{,}000$ resamples. For bounded completion, transition, and invariant proportions, we report exact Clopper--Pearson binomial confidence intervals~\cite{cp34}. To account for the 8-cluster dependency, we implement a cluster bootstrap over the 8 underlying replay clusters following Field and Welsh~\cite{fw07} ($B = 10{,}000$), resampling entire replay clusters with replacement. In addition, we report a leave-one-cluster-out (LOCO) sensitivity analysis to verify whether observed effects depend on individual influential replay clusters. All reported bootstrap confidence intervals are descriptive measures of parameter dispersion across resamples; no formal null-hypothesis significance tests or $p$-values are evaluated.
