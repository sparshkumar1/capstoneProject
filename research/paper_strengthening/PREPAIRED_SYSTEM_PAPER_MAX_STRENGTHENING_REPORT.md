### 2.5 A new, small, real behavioral experiment: the follow-up mechanism's live-model probe (partially closes the single most-repeated open item across all four prior passes)

Every one of the four prior passes flagged the same gap without executing it: the evidence-gated follow-up mechanism had only ever been tested structurally (JSON parses, passes validators, doesn't repeat the question) — never against the real model's actual generated text for whether it targets the specific gap it was asked to probe. This pass built and ran `followup_behavioral_probe_v1.py`: five constructed cases (misconception, missing concept, below-threshold score, weakest gap, and a combined case), each passed through the real, unmodified `generate_followup()` coroutine (the actual in-process GGUF model — confirmed by the run's own environment report, `MOCK_MODE: false`, `active_model_key: qwen_1b`).

**Result, and a defect found and fixed:** the first run surfaced a genuine, previously undocumented prompt-construction defect — the `TASK` directive line in `_build_followup_prompt` named only `missing_str`, so a follow-up triggered *solely* by a misconception or an unresolved `weakest_gap` (both realistic production cases, confirmed by tracing `weakest_gap`'s actual construction in `services/evaluator/app.py:521-529`) received a vacuous "targeting the missing concepts: None identified" instruction despite the correct evidence being listed earlier in the same prompt. **Fixed:** the TASK line now targets whichever evidence category is populated, in the same misconception > missing-concept > weakest-gap priority already used by the orchestrator's own trigger logic; three new regression tests added (`tests/unit/test_qwen_followup_feedback.py`, 47/47 passing after the change, zero regressions in the targeted suite). Re-running the probe confirmed the fix: the previously-vacuous case now generates a correctly targeted question.

**A self-caught methodological error, disclosed rather than hidden:** the probe's first version used an unrealistic, long, hand-written `weakest_gap` sentence, which surfaced a *second*, different defect (the deterministic fallback template breaks on long free-form text) — but tracing the evaluator's real code showed `weakest_gap` is always one of five short, fixed-form phrases in production, so this second defect is disclosed as real-but-unreachable-in-practice, not fixed, and the probe's test input was corrected before drawing conclusions. This self-correction is recorded transparently in both the manuscript (§VII) and the claim ledger (SP-49, SP-50), consistent with this engagement's established practice of disclosing its own investigative errors rather than quietly editing them away.

**Scope, honestly stated:** N=5, one real-model call per case, non-deterministic LLM sampling (confirmed — re-running the same case produced differently-worded but similarly-grounded text across runs), no repetition, a coarse keyword-overlap heuristic for "targeting" (not a semantic-groundedness measurement). This is a small, indicative, disclosed behavioral probe — the first of its kind for this mechanism in this project — not a powered or statistically analyzed study, and is described as such in the manuscript.

### 2.6 An internal numerical inconsistency, found by the independent-reviewer pass and fixed

Re-running `reanalyze_evaluator_ablation.py` (fixed seed 20260921) confirmed Table X's numbers were the correct ones for a section whose entire stated purpose is the question-clustered analysis (the script's own output explicitly labels the item-level figures "cross-checks against the frozen ablation CSV, not new results"). **Fixed:** the Abstract and §XI.1 prose now match Table X. The qualitative conclusion (R-only at least as predictive as the full composite) is unchanged by this correction — only the specific point estimates cited in prose were wrong, and only in the direction of slightly overstating the gap between them (0.483 vs. 0.381, a 0.102 difference, versus the correct 0.496 vs. 0.414, a 0.082 difference).

6. **Are the baselines appropriate?** Yes — component-ablation baselines for the evaluator (every subset of S1/S2/R), and Fixed/Heuristic/Constant-Same for the RL controller, all under identical guardrails and identical evaluation protocol. **Resolved.**
7. **Are negative results handled honestly?** Yes — this is the document's clearest strength. PPO's non-advantage, the full evaluator composite's underperformance relative to R-only, three independently failed adversarial-fix attempts (§XI.1c), and the checkpoint-selection result's per-seed non-uniformity are all reported with the same prominence as positive findings, not buried. **Resolved.**
8. **Are the statistical analyses valid?** The question-clustered bootstrap is a genuine, appropriate correction over naive case-level resampling for this benchmark's 8-question structure, and — after this pass's fix (§2.6) — the prose now correctly reports it. Remaining concern, disclosed but not fully mitigated: dozens of individual adversarial probes and fix attempts appear across the document's history with no multiple-comparisons correction; the document is honest that each is exploratory/hypothesis-generating, but a reviewer could reasonably ask for that framing to be stated once, explicitly, as a section-level caveat rather than left implicit in each individual finding's wording. **Partially resolved — not corrected in this pass** (a wording addition, not a new analysis, and outside this pass's chosen scope; flagged as a specific, low-cost next step in §5).

11. **Are the limitations sufficiently transparent?** Yes, and extended further by this pass's data-flow finding (§2.4). **Resolved.**
12. **Are there contradictions between the abstract, results and conclusion?** One real contradiction was found and fixed in this pass (§2.6 — the item-level-vs-question-clustered statistic mismatch). No further contradiction was found in this pass's review, but this checklist item is inherently incomplete for a document of this length reviewed once; it is not asserted that no further inconsistency exists. **Resolved for the instance found; residual risk disclosed.**
13. **Likely major reviewer objections, ranked:**
    a. *"This reads as an engineering audit, not a research contribution — what is the generalizable finding beyond this one codebase?"* The paper's own framing anticipates this but does not fully resolve it; the Related Work addition (§2.2) helps by situating the PPO-vs-constant-heuristic finding and the LLM-grading-injection concern within a broader literature, but a reviewer at a research (rather than systems/tools) venue may still push back. **Unresolved, requires a venue-fit decision, not a further edit.**
