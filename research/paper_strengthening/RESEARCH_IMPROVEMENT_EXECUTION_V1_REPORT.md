## 2. Speaking-rate defect — executed: sweep, fix, and regression tests

**Sweep before the fix** (`research/paper_strengthening/scripts/speaking_rate_sweep.py`, run with label `before`; output `results/speaking_rate_sweep/sweep_before.json`): confirmed the defect is total, not partial — every WPM value tested from 40 to 320 (spanning far below to far above any realistic human speaking rate) produces the exact same worst-case output (`rate_score=0.0`, `hesitation_rate_deviation=1.0`), because all of them, misread as words/second, exceed the scorers' `_clamp` saturation point. A genuinely WPS-scale sweep (0.5–6.0) confirmed both scorer functions work correctly when given correctly-scaled input. The invalid-input sweep additionally found a related, previously undocumented defect: a non-numeric `true_speaking_rate` value crashes `hesitation_scorer.score_hesitation` with an unhandled `TypeError`, while `confidence_scorer` already degrades gracefully to a default via its existing `_get()` wrapper.

**Fix applied** (smallest-scope, at the point of use, not at the field's source): `agents/audio/confidence_scorer.py` and `agents/audio/hesitation_scorer.py` now divide the incoming `true_speaking_rate` by 60 before comparing it against the words-per-second threshold. The field's definition was deliberately left unchanged at its source (`agents/audio/transcriber.py`) and in the orchestrator's pass-through (`interview_orchestrator.py:2034`), because four other places in the codebase (the orchestrator's own field and three `verify_stage11_*` scripts) already correctly treat it as WPM; changing the source would have broken those instead. `hesitation_scorer.py`'s fix also preserves its distinct "assume optimal (3.2) when the field is absent" default (as opposed to `confidence_scorer.py`'s "assume worst" default for a missing value) and now catches non-numeric input gracefully rather than raising.

**Sweep after the fix** (label `after`; `sweep_after.json`): the rate term now discriminates properly across the full realistic range — scores rise smoothly from 0.21 (40 WPM, very slow) to 1.0 across 126–258 WPM (the realistic 2.1–4.3 words/sec optimal band, expressed correctly in WPM for the first time), and fall again for 280–320 WPM (very fast). The exact boundary values (126 and 258 WPM) score exactly 1.0; one WPM below/above each does not. The previously-crashing non-numeric-string case now degrades to the optimal-default behavior instead of raising. One pre-existing anomaly, unrelated to the WPM/WPS bug and out of this fix's minimal scope, was found and left disclosed, not fixed: a literal `NaN` input causes `_clamp()`'s own `min`/`max` comparison semantics to silently produce a best-case (not worst-case, not an error) score, both before and after this fix — a `_clamp`-level gap shared by several other fields in `confidence_scorer.py`, out of scope for a minimal, single-defect correction.

**Regression tests added** (`tests/unit/test_speech_pipeline.py`): two existing tests' fixture values were corrected from WPS-scale numbers written directly into the `true_speaking_rate` field (which, given the field's real WPM meaning, were testing unrealistic near-zero rates) to their WPM-scale equivalents, preserving each test's original intent under the now-correct unit interpretation. Three new tests were added: realistic-range discrimination, exact WPS-boundary-in-WPM-terms, and invalid-input non-crash coverage (zero, negative, non-numeric, and entirely missing).

**Verification that unrelated components are unaffected:**
- `research/scripts/execute_paper3_study.py` (the frozen P3 study) has zero references to `agents.audio`, `confidence_scorer`, or `hesitation_scorer` — confirmed by direct grep; the frozen PPO/guardrail results are untouched by construction, not merely by assumption.

## 5. Multimodal assessment — protocol prepared, not executed

Per item 7's gate, the confidence/hesitation feature ablation was not run as a new experiment in this pass. What changed since the prior audit: the speaking-rate fix (§2) means any future ablation would test the *corrected* signal, not the broken one — running it before the fix (as the prior state of the code stood) would have measured a term that was constant by construction. **Ground-truth availability, checked in this pass:** no dataset pairs real speech delivery with an independent, validated competence or confidence label anywhere in this repository; the only labeled data (`research/data/evaluator_benchmark/final_human_gold.csv`) rates *answer content*, not *delivery*, and was produced from text, not audio. **This means any confidence/hesitation ablation currently available would have to be a diagnostic (internal feature-sensitivity/ablation) study, explicitly labeled as such, not a validity study against real ground truth** — consistent with the task's own instruction to label diagnostics as diagnostics when ground truth is unavailable. A protocol for this (text-only vs. audio-feature-present ablation, using the evaluator's own text-based score as a partial, explicitly-caveated reference point, never as validated ground truth for delivery) is recommended as the next item to draft and register, not run today.
