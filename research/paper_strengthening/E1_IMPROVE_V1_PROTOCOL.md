# E1-Improve V1 — Bounded Development-Only Improvement Iteration (EXPLORATORY)

**Status: exploratory, development-only, one bounded iteration, authorized by explicit user instruction (this session).** Not a confirmatory experiment. Uses `EVAL_SEEDS_DEV = [1001,2002,3003,4004,5005]` only; `EVAL_SEEDS_CONFIRMATORY` (21021-40040) and the 3 held-out profiles are not touched. No reward/state/action/guardrail/evaluator-scoring definition is changed. Original E1 primary/extended checkpoints, logs and reports (`research/paper_strengthening/results/e1_training*/`, `e1_dev_eval*/`, `E1_DEVELOPMENT_RUN_REPORT.md`) are preserved unmodified; every new artifact goes to new, separate paths.

## 0. Motivation (from `E1_DEVELOPMENT_RUN_REPORT.md` §6)

B2's decisive advantage over B0 at the primary budget (24,576 steps) is reproducible across all 5 training seeds (lucky_guesser-cell MAE identically 0.1636 at every seed) but collapses at the extended budget (98,304 steps, all 5 seeds converge to MAE=1.0000, identical to B0/Condition A). Two code-verified, pre-existing (not newly introduced) mechanisms plausibly contribute to training/evaluation distribution shift, both already partly documented in `research/CANONICAL_SCIENTIFIC_TRUTH_CURRENT.md` §D.1 or newly confirmed here by direct code reading:
1. **Episode horizon mismatch:** training uses `InterviewEnv`'s default `max_steps=15` (unchanged by `AlignedInterviewEnv`/`e1_train_condition_b.py`); evaluation (`x3a_lib.simulate`/`e1_simulate_adapter.simulate_diverse`) uses `max_steps=10`. Documented in canonical truth for the original P3 study; confirmed to apply identically, unmodified, to E1.
2. **Difficulty step-size mismatch, newly confirmed by direct reading of `rl/env/interview_env.py:401-405`:** during training, `self.difficulty` moves by **±0.1** within `[0.1, 1.0]` per action; at evaluation, `cur` moves by **±1.0** within `[1,5]`, i.e. `±0.2` once normalized (`cur/5.0`) — evaluation moves the normalized difficulty **2× faster per action** than training exposed the policy to. Training's initial difficulty is also `Uniform(0.3,0.7)` (`interview_env.py:306`) vs evaluation's fixed `0.6` (`cur=3.0/5.0`). Neither is modified by this iteration; both are pre-existing, frozen environment behavior.

These are plausible contributors to why *more* training (which further optimizes toward the training-time dynamics) could specifically erode a policy behavior that happens to work at evaluation-time dynamics. This motivates Intervention A below. Separately, `RL_GUARDRAIL_COVERAGE_DECOMPOSITION_REPORT.md` (this session, prior phase) already established that PPO has **zero training exposure** to the specific state quadrant (`perf>=0.90, conf<0.40, hes>0.60` — reusing `x3a_lib.shield()`'s own already-validated G6 "nervous" exclusion thresholds verbatim, not new numbers) where the lucky_guesser-style blind spot lives, and that this exact quadrant is where B2's fragile advantage and Heuristic's stable advantage both concentrate. This motivates Intervention B.

## 1. Intervention A — B2 checkpoint-interval trace (new training, exploratory)

**Hypothesis:** if the primary-budget (24,576-step) advantage is a broad, stable plateau rather than a narrow spike, nearby checkpoints (e.g. 16,384–32,768 steps) should show comparably low `lucky_guesser`-cell MAE; if it is a narrow, non-robust spike, only a thin window of checkpoints will show it.

**Design:** retrain B2 only (B0 was not flagged as unstable: quartile-rise ratio 5.77%, below the 10% trigger) for the same 5 seeds `[42,123,456,789,999]`, same config (`e1_config.json`, unchanged), to the extended budget (98,304 steps), with an added `stable_baselines3.common.callbacks.CheckpointCallback` saving a snapshot every 8,192 steps (12 snapshots per seed: 8192, 16384, ..., 98304). This is a purely additive instrumentation change (periodic saving), not a change to any hyperparameter, reward, state, or action definition. Each snapshot is evaluated once on `EVAL_SEEDS_DEV` at the same 24-cell grid used throughout E1. **No snapshot or stopping point is selected using confirmatory data; the trace is reported in full, not cherry-picked.**

**New files (all new, no existing file modified):** `research/paper_strengthening/scripts/e1improve_train_b2_checkpointed.py`, `research/paper_strengthening/scripts/e1improve_eval_checkpoint_trace.py`. Outputs: `research/paper_strengthening/results/e1improve_checkpoint_trace/`.

## 2. Intervention B — narrowly-scoped deterministic PPO+Heuristic gated hybrid (no training)

**Design:** a new, deterministic policy wrapper, `gated_policy(ppo_policy, heuristic_policy)`, evaluated purely at inference time on already-existing, already-frozen checkpoints (Condition A, and B0/B2 primary for reference) — **no retraining, no new checkpoint**. At each step: compute PPO's raw proposal; if the pre-shield state satisfies `perf >= 0.90 and conf < 0.40 and hes > 0.60` (verbatim `x3a_lib.shield()`'s own "nervous" exclusion condition for G6, reused unmodified — not a new threshold), use the Heuristic's raw proposal instead of PPO's for that step only; otherwise use PPO's raw proposal unchanged. The registered, unmodified `x3a_lib.shield()` is then applied to whichever raw proposal results, exactly as for every other condition in this study. This uses only information already in the standard 6-D observation (verified in §2 of the accompanying report: neither the heuristic nor this gate condition reads persona identity, target difficulty, or any value outside `[perf, avg_perf, conf, hes, progress, difficulty]`).

**Rationale for the specific gate condition:** it is exactly the state region `RL_GUARDRAIL_COVERAGE_DECOMPOSITION_REPORT.md` already established PPO has 0% training exposure to and 0% observed correct-Harder agreement in (this session, prior phase); it reuses an existing, already-validated threshold from the frozen shield rather than a newly tuned one; and it is the same region responsible for both B2's fragile advantage and the Heuristic's stable one, per §0 above.

**New file:** `research/paper_strengthening/scripts/e1improve_hybrid_gate.py`. Evaluated with the existing `e1_dev_eval.py`-style harness on `EVAL_SEEDS_DEV`, the same 24-cell grid, for: Condition A+Gate, B0(primary)+Gate, B2(primary)+Gate — compared against the unmodified Condition A, B0, B2, Constant-Same+G, Heuristic+G already reported in `E1_DEVELOPMENT_RUN_REPORT.md`.

## 3. Decision criteria (fixed here, before running either intervention)

- **Intervention A:** report the full per-checkpoint MAE trace (all 12 snapshots × 5 seeds); no single snapshot is declared "the" answer — the trace itself, and whether a wide or narrow plateau exists, is the result.
- **Intervention B:** the gated hybrid is judged a genuine improvement over its own base checkpoint if pooled dev MAE improves with no per-cell regression ≥0.05 MAE units relative to that same base checkpoint ungated (identical rule to E1 V4's own B2-vs-B0 regression check, reused for consistency). It is judged competitive with Heuristic+G if its pooled MAE is within 0.02 of Heuristic+G's 0.2674 (primary-budget reference).
- Neither intervention is selected, retried, or threshold-adjusted using its own result; both are run once and reported in full, including if inconclusive or negative.
