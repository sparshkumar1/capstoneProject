# Research Strategy — PrepAIred Full-System Paper

**Status:** Phase 1 (read-only analysis). No code changed, no experiment run, no checkpoint touched. Scope: the full-system paper (`final_prepaired_ieee_paper.pdf` / `final_prepaired_ieee_paper_REVISED.md`), not P1 (security) or P3 (RL-only) as separate papers — though both are drawn on as evidence about this same system where applicable, per the governing prompt's instruction.

## 1. What is genuinely distinctive about the complete system

Reading the implementation against the manuscript, the defensible distinctive claim is architectural, not algorithmic: PrepAIred wires together (a) a three-signal technical evaluator, (b) a score-independent speech-delivery channel, (c) an RL difficulty controller, and (d) an evidence-gated LLM follow-up/feedback layer into one continuous, low-latency session loop, with the LLM deliberately stripped of scoring authority. No single component is novel — SBERT, CrossEncoders, PPO, and grounded LLM generation are all established techniques (Table I of the manuscript says this correctly). The combination, and specifically the *decoupling discipline* (numeric authority never delegated to the LLM; speech signal kept out of the technical score; follow-ups bounded and evidence-triggered rather than LLM-initiated) is the part that is actually yours to claim.

This means the strongest paper is not "we built a system that works," and not "our RL controller is better," but: **a systems paper that states its design commitments explicitly and then tests each one against what the implementation actually does** — the same discipline that produced a defensible P1. Applied here, it produces a paper that is honest about which commitments held and which did not, which is more defensible than a paper claiming uniform success.

## 2. Established engineering vs. defensible research contribution

| Component | Established technique | What (if anything) is a research contribution here |
|---|---|---|
| S1 (SBERT similarity) | Fully established (Reimers & Gurevych) | None claimed; used as one input |
| S2 (concept coverage + dampening) | Threshold-based coverage is established; the *dampening-on-low-reasoning* rule (Eq. 3) is a specific, testable design choice | Whether dampening measurably reduces keyword-stuffing false positives is an answerable, not-yet-answered question (§3A below) |
| R (CrossEncoder reasoning) | Established architecture; the specific checkpoint is a partial in-house derivative | The checkpoint's own value-add over S1/S2 alone is already measured in frozen data (§3, RQ1) — this is real evidence, already in hand |
| PPO difficulty controller | Established algorithm (Schulman et al.) applied to a bespoke 6-D state | The controller's comparative value under guardrails has already been tested and the frozen result is negative (equivalence to constant-difficulty). This is not a contribution to claim as a success; it is a contribution as an honestly reported negative/mechanism finding |
| Deterministic follow-up gate | Rule-based state machine — an engineering pattern | Whether the gate changes generation behavior relative to no gate (or a simpler gate) is not yet measured |
| Speech confidence channel | Standard prosodic features (Praat-style) combined via a hand-set linear weighting | The channel is implemented, but a verified unit-mismatch defect (§4 below) currently prevents one of its five weighted terms from functioning as designed on real audio |

## 3. Strongest findings already supported by reproducible, frozen evidence (no new experiment needed)

These are sitting in the repository, audited, and can be written into the paper as-is, with correct framing:

- **RQ-Evaluator:** *Does the full hybrid weighting (0.15/0.35/0.50) outperform simpler component combinations at tracking human-rated answer quality?* Frozen `research/results/paper2/paper2_ablation_results.csv` already contains exactly this ablation grid (S1 only, S2 only, S1+S2, R only, S1+R, S2+R, full composite) against the 64-item human-rated benchmark. Point estimates: full composite ρ=0.3812 is *below* R-only (0.4832) and S1+R (0.4884). Confidence intervals substantially overlap ([0.16,0.58] vs [0.25,0.68] vs [0.26,0.68]), so this cannot be reported as a statistically confirmed difference — but it is a legitimate, already-collected data point that the manuscript should report honestly rather than omit: **the full weighting is not shown to help, and the simpler R-only or S1+R combinations are at least as good on this benchmark.** This directly answers part of the "is the hybrid architecture empirically justified" question the governing prompt asks for, using zero new experiments.
- **RQ-RL:** *Does PPO add measurable value over simpler difficulty policies under the same guardrails?* Already answered, frozen, and audited: no. Constant-"Same" + guardrails ties PPO + guardrails (MAE 0.673–0.687, identical actions on 120/125 sessions); a threshold heuristic (MAE 0.473) beats every PPO variant. The guardrail layer, not the learned policy, explains the gain over an unguarded fixed baseline. This is a real, reportable, mechanism-level finding — the paper's honest empirical center of gravity, if the paper leans into it rather than around it.
- **RQ-Speech (new, found in this pass):** *Does the speech-delivery channel function as designed?* No, for the "speaking rate" term specifically. The live transcriber (`agents/audio/transcriber.py:221`) computes `true_speaking_rate` in **words per minute**; the scoring functions that consume it (`agents/audio/confidence_scorer.py:40-44`, `agents/audio/hesitation_scorer.py:52-57`) assume **words per second** (threshold 2.1–4.3, center 3.2 — the code comment says so explicitly). A deterministic check run in this pass (real functions, representative WPM inputs 100/140/160/181, no new data collected) confirms `rate_score` is exactly 0.000 and `rate_deviation` is exactly 1.000 at every realistic real-world speaking rate. This zeroes out 13% of the confidence-score weighting and maximizes the corresponding hesitation term for every real session, regardless of actual delivery quality. This is verifiable from the code alone and is arguably the single most concrete, novel, falsifiable finding available for this paper.

## 4. Candidate research questions (select from, do not run all)

In priority order, matched to what the system and existing evidence can actually support:

1. **Primary candidate:** *Where does a decoupled, evidence-gated interview-assessment architecture's behavior diverge from its stated design commitments, and what does that reveal about validating such systems before deployment?* This frames the paper around the three concrete divergences already established (hybrid-weighting not shown to beat simpler combinations; PPO not shown to beat guardrails-only; the speech-rate channel provably inert on real audio) plus what *did* hold (score-suppression from the LLM; deterministic follow-up bounding; technical/speech score separation, confirmed by code review). This needs no new experiments to state the first two findings and only the deterministic-verification step (already done) for the third — new experiments would only be needed to go *further* (e.g., quantify the speech-rate fix's effect, or explain the PPO null result mechanistically), which is optional strengthening, not a precondition for a defensible paper.
2. **Secondary candidate, if resources allow new experiments:** *Does concept-coverage dampening (Eq. 3) measurably reduce false-positive scoring of keyword-heavy, poorly-reasoned answers, relative to undampened coverage?* Answerable via re-analysis of the existing 64-item benchmark's category labels (some categories are explicitly "keyword-heavy without reasoning" per the canonical benchmark description) — this may require only a new *analysis script* against already-frozen, already-collected data, not new measurements, and should be scoped as such before deciding whether it needs formal preregistration.
3. **Tertiary, requires new experiments if pursued:** *Does the deterministic follow-up gate change LLM output behavior relative to no gate or a naive always-follow-up baseline?* No existing data addresses this at all (X1-B never exercised a live follow-up, per prior P1 audits). This is the one candidate question that would require genuinely new experimental data collection, and per project rules needs a registered, hashed, git-tagged protocol before any run.
4. **Not recommended as a headline RQ:** re-litigating whether PPO can be made to work with a different reward/state design. This is legitimate follow-up work, but per project rules it requires explicit approval to modify reward/state/action definitions or retrain, and a paper built around "we redesigned it and now it works" carries a high risk of test-set contamination (tuning against the same evaluation scenarios) unless a strict held-out split is pre-registered first. Recommend keeping this out of scope for this paper and flagging it as future work.

## 5. Recommended framing

Adopt the primary candidate (§4.1) as the paper's spine: **a full working system, described accurately, with a scoped audit of where its behavior does and does not match its design intent.** This is the same discipline that produced a defensible P1 (Position C: system + scoped evaluation, evaluation-primary), applied to this different system. It requires no new experiments to be truthful and complete as a first pass; it becomes strictly stronger with the optional Phase-3 experiments in `EXPERIMENT_PLAN.md`, each gated on explicit approval before execution, per this project's standing preregistration rule.

## 6. What this strategy deliberately does not do

- It does not propose redesigning the RL reward, state, or action space "to get a better result." That is explicitly gated by project rules ("do not change reward/state/action definitions or retrain PPO without explicit approval") and is the highest-risk path to an unintentionally invented or overfit result.
- It does not propose a new human-rated benchmark (the user's message explicitly excludes new real-participant studies).
- It does not merge this paper's scope with P1 or P3 as separate contributions; where their frozen evidence bears on this exact system (the CrossEncoder correlation table, the PPO/guardrail study), it is cited as evidence about this system, not re-derived.
