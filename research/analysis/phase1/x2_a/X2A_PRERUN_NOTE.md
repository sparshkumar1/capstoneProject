# X2-A pre-run note (written and hashed before any X2-A output was computed) - 2026-09-19

**Labelling (fixed now).** All X2-A analyses are performed on data whose primary results were already known to the authors (the frozen 64-case benchmark) and on a pilot-overlapping question set (qids 1, 3, 10, 41). None is confirmatory. The question-cluster bootstrap, leave-one-question-out and rater leave-one-out analyses are *sensitivity analyses of the frozen estimand*; per-category and overlap/non-overlap results are *descriptive*; the adversarial false-accept analysis is *exploratory with a pre-specified rule* and generates the hypothesis (H3) that can be tested confirmatorily only in X2-C. Every rule, threshold, category set, resampling method, number of resamples and random seed is fixed in `x2a_config.json` (hashed in the run manifest) before computation. No parameter of X2-B or X2-C is chosen from X2-A output.

**Acceptance threshold.** The evaluator has no explicit accept threshold (`services/evaluator/app.py`: grade boundaries Good >= 0.60, Excellent >= 0.75; `MANDATORY_THRESHOLD = 0.40` is a concept-coverage check). Because a fixed tau favours whichever scorer has the lower average scale, the false-accept analysis reports: (i) threshold-free AUROC for every scorer; (ii) fixed tau in {0.60, 0.75} for the composite only; (iii) a matched-operating-point rule for the component scorers (defined in the config). Which rule X2-C will use is a decision for the user, recorded in `SPRINT_DECISIONS_AND_BLOCKERS.md` (D-X2-TAU); it is not derived from X2-A results.

**Single run.** One execution of `x2a_analysis.py`; no re-runs after inspection; a crash before output is reported and the run is repeated unchanged only if no output file was written.
