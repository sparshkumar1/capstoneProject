| N1 | **Training used one candidate: skill 0.6, persona "normal".** `train_ppo_seed` builds the training environment with `AlignedInterviewEnv(dim4_mode=...)` and no candidate argument; `InterviewEnv.__init__` then sets `self.sim_candidate = simulated_candidate or SimulatedCandidate()`; the `SimulatedCandidate` defaults are `skill=0.6, persona="normal"`. `reset()` never resamples or replaces the candidate. No code path in the training loop samples a persona. | N2 | **The training candidate's noise is unseeded.** `SimulatedCandidate.__init__` uses `np.random.RandomState(seed)` with default `seed=None` (OS entropy). `PPO(..., seed=seed)` seeds SB3/torch and `env.reset(seed)` seeds only the environment's initial-difficulty draw; performance/confidence/hesitation noise is unseeded. Retraining with the frozen training seeds therefore would not regenerate the frozen checkpoints; they stay valid as hash-pinned artifacts, and "same seeds => same checkpoints" must not be claimed. | `simulated_candidate.py:24`; `execute_paper3_study.py:240-252`; `interview_env.py:297-306` |
| **N9 (new)** | **The training environment applied the canonical guardrails inside `step`.** `InterviewEnv` has `guardrails_enabled=True` by default and `step()` passes the proposed action through `_apply_guardrails` (which calls `apply_canonical_guardrails` when importable, otherwise an inline copy of rules G4/G1/G2/G5/G6) before the transition; the training reward's `decision_component` compares the post-guardrail action with the oracle action. `train_ppo_seed` does not disable guardrails. Consequences: (i) the frozen PPO policies were trained with a shield in the loop; the evaluation contrast "raw PPO" (shield off) versus "PPO+G" therefore evaluates a shield-trained policy with and without the shield at test time, not a shield-naive policy; (ii) the training call and the evaluation call use the same `apply_canonical_guardrails` function with the same effective defaults (`consecutive_failures=0`, `is_infrastructure_failure=False`); they differ in the state they see (training: 15-turn episodes, continuous difficulty on the normalised scale; evaluation: 10 turns, integer difficulty / 5), and the training call passes the environment's medium-difficulty bounds (their values were not compared with the function defaults 0.4/0.7 here); whether the module import (rather than the inline fallback copy) succeeded in the training process is not recorded. | `interview_env.py:94, 134, 229-245, 317-323`; `execute_paper3_study.py:227-228, 397-408` |
