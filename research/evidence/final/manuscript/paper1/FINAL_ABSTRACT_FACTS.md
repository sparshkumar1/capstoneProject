# Paper 1 - abstract facts (all from stored artifacts; see research/evidence/final/PAPER1_FINAL_CLAIM_MATRIX.md; wording narrowed after the independent Antigravity methodology review)
- System: LLM-assisted technical-interview practice pipeline (orchestrator, evaluator service, local Qwen 1.5B feedback service, Docker C sandbox, SQLite). Engineering evaluation in one environment (Windows 11 + WSL2 + Docker Desktop + local image); no users.
- Method: three campaigns (containment X1-C, fault injection X1-A, Qwen fixed-turn invariance X1-B-I), each with controls; protocols committed and tagged locally (unpushed) before execution; the same agent designed and ran them; an independent read-only Antigravity methodology review was completed, verdict METHODOLOGICALLY SOUND ONLY AFTER CLAIM NARROWING (no blocker), and the statements below use the narrowed wording; two builds (A = baseline SUT release/app-repair/v1, B = repaired SUT sut/X1/build-B after two repairs), both reported. The five repetitions per scenario are deterministic repeatability checks, not samples; no inferential statistics are attached.
- Containment (X1-C): on one Docker Desktop (WSL2) machine, for the nine attack programs tested under the predefined harness and controls, the shipped configuration met the prespecified containment/host-unchanged criteria in 5/5 repetitions per attack on both builds; weakened/permissive controls produced the expected breaches (5/5) where a control applies; benign control 10/10. Qualifiers: SEC-01 was blocked by the literal pre-flight filter and ptrace(TRACEME) returned 0 in the container when the filter was bypassed (this is not a Docker-isolation result for ptrace); socket() succeeds but connect() fails without a network; executor status strings (e.g. wrong_answer) did not discriminate for SEC-02/07/08/09, so host/runtime observables were needed; the SEC-09 permissive-control canary reset had a methodological flaw and the SEC-08 oracle references a SUT constant.
- Fault injection (X1-A): build A - nine of twelve scenario rows met 5/5 (FLT-04 counted as four rows), the tested evaluator outage was recorded as a 0.0 score with no flag (0/5), the tested compiler timeout left a running container (5/5 runs), one timing-bound miss (FLT-07b 4/5). Build B - every executed scenario 5/5: the tested evaluator-outage scenario was detected and handled as an infrastructure failure without a scored result, and the tested compiler-timeout scenario was terminated with container cleanup. FLT-05 injected a missing Docker CLI (not an unreachable daemon); FLT-08 (WebSocket) and FLT-09 (audio) not executed; no general fault-tolerance claim.
- Invariance (X1-B-I): build A - 72 pairs, 16 valid LLM-sourced (registered minimum 30 not met), 72/72 equal; build B - 72 pairs, 72 valid; under the fixed-turn test (fixed evaluator output) the 14 compared technical observables were byte-identical across benign/adversarial arms in 72/72 valid pairs, mutation control detected 72/72, static AST guard 0 flagged with the injected mutant caught. This does not establish that Qwen can never influence future scoring or downstream behaviour. Injections' steering effect not demonstrated.
- HIGH limitations (state all four): (1) NaN, Inf and negative evaluator outputs become 0.0 rather than infrastructure failures, so FLT-04 is a numeric-range sanitization observation only; (2) the separate Qwen follow-up generation channel, whose text and target concepts can enter the evaluator's expected-concepts path, was not tested; (3) SEC-01 containment depended on literal preflight filtering, with ptrace(TRACEME) returning 0 in the container once bypassed; (4) the shipped Qwen client timeout is 6 s while local CPU generation took about 19-30 s, so local generation times are not evidence that the shipped 6 s path completes them.
- Other constraints: unresponsive-daemon case not campaign-tested (an unregistered single probe took ~17 s to a structured error); some X1-A timing SLAs derived from internal SUT constants (circularity concern).
- Required qualifiers: single environment, no cross-platform generality; nine programs; local unpushed tags; independent methodology review completed (sound only after claim narrowing). Never claim formal security, universal sandbox isolation, fault tolerance as a general property, that all faults are handled or all attacks contained, or that Qwen can never influence future scoring.
