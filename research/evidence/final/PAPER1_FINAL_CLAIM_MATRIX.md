# Paper 1 — final claim matrix (2026-09-20)

**Frame.** Failure-aware orchestration of an LLM-assisted technical-interview system, with a controlled containment campaign for the code sandbox and an invariance test of score observables against LLM-authored text. Every experiment below was designed, written, registered (local annotated tag before execution; repository never pushed) and executed by the same agent (Claude) and **has had only a self-audit** (`X1_METHOD_AUDIT.md`), not an independent review. Build A = `release/app-repair/v1` (`980747ff…`); build B = `sut/X1/build-B` (`beb374f3…`, repairs FLT-03, FLT-06, `llm_status` truthfulness, Qwen token cap). Replicates are deterministic re-runs, not samples: "k/5" is a repeatability count, no interval is reported. **Never write:** secure, isolated, escape-proof, fault-tolerant, zero violations, formal authority separation, trustworthy, "shield" for the guardrail, "preregistered" without the local/unpushed qualifier.

## Removed / not supported
"Secure", "isolated", "escape-proof", "zero violations", "fault-tolerant", "formal shield", "the LLM cannot influence scoring", "authority separation proven", any claim about WebSocket or audio faults, any claim about follow-up questions being isolated, any real-user or latency-guarantee claim, "first"/"novel" (the literature search found no direct precedent for measured degradation of an LLM-assessment pipeline; absence is not proof).

## Cross-cutting limitations to state
Single machine; author-written and self-audited; same-agent repair-and-retest (regression check, not independent); replicates deterministic; local unpushed tags; nine attack programs; Qwen stub in X1-A; the whole system runs on a `.venv` that violates its pins (registry X-C004).
